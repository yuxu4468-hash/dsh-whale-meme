# dsh-whale-meme

把**表情包绘制工作区**的工作流固化成一个可安装的 [DeepSeek Harness](https://deepseek.com)（DSH）插件：
一个 14 个 action 的校验／素材下载／起草／预览／出图工具，加一份工作流技能。

> **唤醒词：蓝色大肥鱼表情包绘画** —— 说这句话就会进入本工作流（见[使用教程](#使用教程)步骤 0）。

> **这个仓库只有代码和文档。** 不含任何角色立绘、参考语料、出图产物或提示词成品。
> 角色与语料的授权见 [NOTICE.md](NOTICE.md) —— 它们仍然只归原作者与二次设计者。

- **授权**：[CC0 1.0 Universal](LICENSE)（公有领域奉献）
- **依赖**：无第三方运行时依赖，只用 Node 内置模块
- **构建**：无构建步骤，`lib/*.mjs` 是原生 ESM

## 它解决什么问题

表情包工作流的规则通常是散的：散在几个 `README.md`、几份协作说明、一份验收清单，和一堆 Python 脚本里。
新会话要全部读一遍才知道「谁写哪个目录、投喂文本不能手打、一次不能画两格」。

这些规则里有一部分**可以被机器判定**，另一部分不能。插件把前者变成工具，把后者变成技能正文：

| | 内容 | 形态 |
|---|---|---|
| 可判定 | 工作区结构、逐字文案、投喂负载是否被改写、产物血缘、产物尺寸与透明通道 | `whale_meme` 工具的 14 个 action |
| 不可判定 | 角色五要素是否保住、情绪反转是否成立、排版是否合规、合规边界 | `whale-meme-workflow` 技能正文 |

工作流里的代价是真实的：一条硬规则漏掉，就是一次付费出图调用。

## 使用教程

这一节从头走一遍完整流程。**每个例子的输入输出都取自真实工作区**，不是示意。

约定：**你** 表示你在对话里说的话，**调用** 表示代理会去调的工具。
你不需要记住 action 名 —— 说人话就行，代理会翻译；但知道调了什么，出问题时好定位。

> 前提：已经[装好并重启](#安装后必须重启)。没重启的话工具和技能都还没注册，步骤 0 就会失败。


### 先确定你走哪条路

| 你的处境 | 从哪开始 |
|---|---|
| **手上只有一句话需求** | [步骤 2 起草文案](#步骤-2-没有现成文案从一句需求起草) |
| 工作区已有任务、提示词已定稿 | [步骤 1 了解现状](#步骤-1-了解现状) |
| 工作区还没有立绘/参考语料 | [步骤 3 准备素材与任务](#步骤-3-准备素材与任务) |
| 只是想知道这个工作区怎么运作 | [步骤 1 了解现状](#步骤-1-了解现状) |

三条路最后都汇到同一处：**文案定稿 → 抽投喂负载 → 出图 → 验收**。

以下是把这条链拆开的样子。**中间两件是「出图前必做」** —— 省了它们就是拿付费调用去赌：

整条链只有四件事，**中间两件是「出图前必做」** —— 省了它们就是拿付费调用去赌：

| 阶段 | 做什么 | 工具 |
|---|---|---|
| ① 看清 | 工作区在哪、缺什么、各任务什么状态 | `status` |
| ② **定稿** | 拿到唯一权威的逐字文案与必加粗的字 | `task`（或 `draft` → `draftCheck` 起草） |
| ③ **验料** | 证明投喂文本没被手打改写 | `payload` |
| ④ 出图 | 调参数 → 看提示词 → 确认 → 出图 → 验收 | `preview` → `render` → `lineage` + `outputs` |

三件配套：

| 场景 | 工具 |
|---|---|
| 工作区还没有素材 | `fetch` 从上游开源仓库下载参考图 |
| 只有一句话需求，还没想好文案 | `draft` → LLM 产出 → `draftCheck` → 你逐字改 |
| 不想让插件出图 | `commands` 拿命令自己执行，其余环节完全一样 |

开新任务的支线：`init`（补目录）→ `scaffold`（建骨架）→ 文案定稿 → `build`（抽负载）。

### 步骤 0 · 怎么唤醒它

最简单的开始方式：**直接说唤醒词**。

```
你：蓝色大肥鱼表情包绘画
```

这句话写在技能描述里，会进入会话的技能目录 —— 所以它一说出来就会命中 `whale-meme-workflow`，
代理随即按本工作流推进。也可以问得更自然：

```
你：这个工作区怎么工作？
调用：命中 whale-meme-workflow 技能
```

界面上你应该看到它开始讲四段流水线、两个模型的差异表、编辑链与环境坑 —— 这说明**技能已注册**。
再让它调一次工具：

```
你：现在这个工作区是什么状态？
调用：whale_meme(action="status")
```

这时应该出现一段以 ✅ 开头的自然语言回复（形如「✅ 工作区在 …」），说明**工具已注册**。

两条都没反应，几乎一定是**没重启**（插件在应用启动时装载）：托盘右键 → 退出，再重新打开。
细节见[安装后必须重启](#安装后必须重启)。

确认装上之后，从[步骤 1 了解现状](#步骤-1-了解现状)接着看；
如果你手上只有一句话需求，也可以跳过，直接去[步骤 2 起草文案](#步骤-2-没有现成文案从一句需求起草)。

### 步骤 1 · 了解现状

```
你：现在是什么状态？
调用：whale_meme(action="status")
```

真实返回（这就是界面上会显示的内容）：

```
✅ 工作区在 F:\whale meme

四个阶段目录：datas✓  texts✓  _tools/payloads✓  outs✓

共 1 个任务：
  · task01 · 字符串替换把脚本改坏了
      提示词 5/5，投喂负载 7 份
      gpt-image-2：7 张图，交付件 05_整图一次出图_1024x1536.png
      gpt-image-2.5-sunburst：7 张图，交付件 05_整图一次出图_1024x1536.png

下一步：看某个任务的逐字文案用 task（例如 task="task01"）；确认投喂文本没被改过用 payload。
```

**看哪里**：

| 想确认的事 | 看哪一行 |
|---|---|
| 插件认的工作区对不对 | 第一行的路径。不对就设 `DSH_WHALE_ROOT` |
| 目录结构缺不缺 | 「四个阶段目录」那一行，带 ✗ 的就是缺，用 `init` 补 |
| 提示词写齐了没 | 「提示词 5/5」；出现「（缺 …）」就是没齐 |
| 有没有图、交付件在不在 | 每个模型那行；出现「没有推荐交付件」要注意 |
| 有没有别的毛病 | 任何 ⚠️ 开头的行 |

如果回复说「没认到工作区」，那是定位问题而不是数据问题，照它给的提示设 `DSH_WHALE_ROOT` 即可。

下一步：有现成文案就去[步骤 2 核对它](#步骤-2-没有现成文案从一句需求起草)；
只有一句话需求就[直接起草](#步骤-2-没有现成文案从一句需求起草)；素材缺就先[准备素材](#步骤-3-准备素材与任务)。

### 步骤 2 · 没有现成文案？从一句需求起草

前面几步都假定文案已经定稿。但实际使用里人往往只有一句话 —— 文案是要边想边改的。
这条路把「想」和「定」分开：**插件不写台词**，它只给模板与校验；文案由 LLM 依你的需求产出，
**再由你逐字确认**。

```
你：我想画一个她发现脚本被改坏了、先得意后破防的两格梗，先给我个草稿
调用：whale_meme(action="draft", narrative="她发现脚本被改坏了，先得意后破防")
```

返回一份待填写的模板（这一步不写文件、不出图）：

```jsonc
{
  "narrative": "她发现脚本被改坏了，先得意后破防",
  "subject": "<这个任务要讲的梗是什么？一句话>",
  "panels": [
    { "marker": "格 1（上格）", "text": "<第一格台词，句末用全角句号。>", "mood": "<情绪，例如：自信满满>" },
    { "marker": "格 2（下格）", "text": "<第二格台词，句末用全角句号。>", "mood": "<情绪反转>", "bold": "<必须加粗的字，没有就留空>" }
  ],
  "style": "anime-cel", "size": "1024x1536",
  "quality": null, "background": null,
  "extra": [], "avoid": [], "palette": []
}
```

代理会照这个结构产出草稿，再调 `draftCheck` 校验：

```
调用：whale_meme(action="draftCheck", draft={ ...填好的草稿... })
```

```
✅ 草稿校验通过。下面这份就是要画进图里的东西，**请逐字校对**：

【文案草稿】字符串替换把脚本改坏了

原始需求：
  她发现脚本被改坏了，先得意后破防

逐字文案（这几个字会被原样画进图里，请逐字校对）：
  [格 1（上格）] 我的字符串替换把脚本改坏了。我直接读取并修复。
        情绪：自信满满
  [格 2（下格）] 文件被我的替换操作整篇损坏。
        情绪：当场破防
        加粗：整篇损坏

出图参数：
  模型      gpt-image-2.5-sunburst
  画风      anime-cel
  尺寸      1024x1536
  配色      深藏青为主

角色剪影三要素（不得丢失）：头侧两片鲸鳍状耳；身后完整大体量双叉鲸尾；深蓝→浅蓝渐变长发＋头顶偏左卷曲呆毛

草稿指纹  82295f9516d4
```

**这一步就是让你改的地方** —— 直接说「下格改成『文件被我改烂了。』」，改完再 `draftCheck` 一次。
草稿指纹会随内容变化，便于确认你复核的是同一份。

校验器会挡住这些（都是实测踩过的坑）：

| 会被挡下的情况 | 为什么 |
|---|---|
| 台词句末不是全角句号 | 验收清单 A 组硬要求，全角句号是唯一允许的句末标点 |
| `bold` 里的字**没出现在台词里** | 最常见的「写了但没生效」：模型无从加粗一个不存在的词 |
| 超过两格 | 本项目实测结论：叙事最多上下两格 |
| `marker` 重复 | 分格对不上，出图会串 |
| 出现「官方」字样 | 非官方同人，验收清单 E 组明令禁止 |
| 透明底配 `gpt-image-2` | 该模型不支持，会被直接拒绝 |
| 还是模板占位符 | 防止把没填的模板当草稿交上来 |

半角标点、连续英文字母只**提醒**不阻断 —— 那可能是你刻意的。

确认无误后接既有流程：`scaffold` 建任务 → 把文案写进 `00_分镜与文案锁定.md` → `build` 抽负载 → `preview` 出图。
（`draftCheck` 会顺带给出可直接落盘的 `storyboardPreview`，并已用同一套分镜解析器验证过自洽。）

#### 已有文案时：直接核对它

```
你：task01 的台词是什么？哪几个字要加粗？
调用：whale_meme(action="task", task="task01")
```

```
✅ task01 · 字符串替换把脚本改坏了

提示词五件套：5/5 份齐全

逐字文案（唯一权威文本，原样照抄，一个字都不能改）：
  [格 1（上格）] 我的字符串替换把脚本改坏了。我直接读取并修复。
  [格 2（下格）] 文件被我的替换操作整篇损坏。
必须加粗（且只有这些）：整篇损坏

核对完就往下：先[准备素材与任务](#步骤-3-准备素材与任务)，再[证明投喂文本没被改写](#步骤-5-证明投喂文本没被改写)。
```

规则只有两条，但都要当真：

1. **`[格 N]` 后面的那句话原样照抄** —— 多一字、少一字、繁体、擅自加标点，都算验收不通过；
2. **只有「必须加粗」列出的那几个字加粗**，其余一律常规字重。

如果回复里出现 ⚠️（例如「文案第 1 行没有以句末标点结尾」），说明你的 `00_分镜与文案锁定.md` 格式有问题。
**先改文案再出图**，不要指望模型自动修好 —— 那正是要花冤枉钱的地方。

### 步骤 3 · 准备素材与任务

#### 素材还没有？先从上游下载

如果 `datas/` 里没有立绘和参考语料，可以从上游开源仓库直接拉 ——
**EDMOK/blue-fish-archive**（本工作区语料的来源，公开仓库）：

```
你：把参考图下载下来
调用：whale_meme(action="fetch")
```

```
✅ 素材下载计划如下（这是预览，还没有下载任何文件）：

  · 角色基准（立绘 + 官方 logo）
      3 个文件，3.2 MB → datas/01_character/
  · 表情包样例与图库清单
      5 个文件，1.1 MB → datas/02_reference_stickers/
  · 社区同人语料缩略图（251 张 webp，约 12.5 MB）
      251 个文件，12.5 MB → datas/02_reference_stickers/previews/

合计 259 个文件，16.8 MB。
上游：EDMOK/blue-fish-archive（main @ 2282e0dc82）

下一步：确认上面这份清单没问题后，加 write=true 才会真正下载（只往 datas/ 写）。

⚠️ 上游素材是 **CC BY-NC-SA 4.0**：保留署名、非商业、相同方式共享；
   参考语料只作风格/题材参考，不得作为成品交付。
```

确认后再说一句「下载」，代理会带 `write: true` 重调。几点要说明：

| | 说明 |
|---|---|
| 怎么下的 | 走 GitHub REST API，**不依赖 git**（本机到 github.com 的 git 传输不通，API 域名正常），也不引入第三方包 |
| 下到哪 | **只往 `datas/` 写**，不碰 `texts/`、`outs/`，也不改 `_tools/` 里的脚本 |
| 挑了哪些 | 只取图片与 json。上游是站点仓库，字体、favicon、二维码、音频、网页本体**一律不下** |
| 体积大的包 | `large`（33.7 MB）与 `media`（242 MB）不在默认组合里；`media` 会明确警告 |
| 来源记录 | 每次下载写 `datas/_fetched/SOURCE.json`：仓库、commit、许可与逐文件 sha256 |
| 速率 | 未认证的 GitHub API 每小时 60 次；251 张缩略图会用到配额，可设 `GH_TOKEN` 提高额度 |

> 实测交叉验证：下载到的立绘 sha256 是 `30c9271ec44a…`，与本工作区出图元数据里记录的参考图 sha 完全一致
> —— 确认下到的就是同一份文件。

#### 开一个新任务

四步，**顺序别颠倒**。

**① 补目录**（工作区可能缺文件夹；只创建、不覆盖）

```
你：工作区还缺哪些目录？
调用：whale_meme(action="init")
```

```
✅ 工作区还缺 1 样东西（这是预览，还什么都没创建）：
  · README.md

已存在、一字未改：datas/01_character、datas/02_reference_stickers、texts、outs、_tools/payloads、.whale、outs/INDEX.csv、datas/02_reference_stickers/README.md、.whale\manifest.json

下一步：确认上面这份清单没问题后，加 write=true 重跑才会真正创建（只创建、不覆盖）。
```

确认无误再说「确认创建」，代理会带 `write: true` 重调。

**② 建任务骨架**（先看计划，确认后写盘）

```
你：帮我开一个新任务，题材是「改需求改到崩溃」，先给我看计划
调用：whale_meme(action="scaffold", title="改需求改到崩溃")
```

```
✅ 这是新任务的计划（预览，还没写任何文件）：task02_改需求改到崩溃

任务目录：F:\whale meme\texts\task02_改需求改到崩溃
将包含 6 个文件：
  · 00_分镜与文案锁定.md（793 字符）
  · 01_提示词_GPT-Image-2.md（982 字符）
  · 02_提示词_GPT-Image-2.5.md（1055 字符）
  · 03_无字底图与后期排版兜底.md（415 字符）
  · 04_验收清单.md（1600 字符）
  · README.md（899 字符）

各文件用途：
  · 00_分镜与文案锁定.md
  · 01_提示词_GPT-Image-2.md
  · 02_提示词_GPT-Image-2.5.md
  · 03_无字底图与后期排版兜底.md
  · 04_验收清单.md

出图产物将来放：F:\whale meme\outs\task02_改需求改到崩溃
投喂负载将来放：F:\whale meme\_tools\payloads\task02

下一步：确认路径与文件名无误后，加 write=true 重跑才会真正创建（拒绝覆盖已占用任务号）。
```

任务号被占用时它会**直接拒绝**并列出冲突路径 —— 工作流规定「只新建 `taskNN_*`，不改动已有任务」。

**③ 定稿文案 + 补抽取计划**（这两件是手工活，插件替不了）

- 把 `00_分镜与文案锁定.md` 的逐字文案改成本任务的：一句一行、句末全角句号、整行括号只写加粗要求；
- 在 `.whale/manifest.json` 给新任务补一段 `extraction`，写法见[投喂负载的抽取计划](#投喂负载的抽取计划)。

**④ 抽负载并复核**

```
你：把这个任务的投喂负载抽出来
调用：whale_meme(action="build", task="task02")            // 先 dry-run 看 sha
调用：whale_meme(action="build", task="task02", write=true)
调用：whale_meme(action="payload", task="task02")           // 复核，应全 ok
```

最后别忘了在 `texts/README.md` 的任务索引里追加一行。

素材与任务都就绪、文案也定稿之后，接着[步骤 4 出图](#步骤-4-出图预览确认验收)。

### 步骤 4 · 出图：预览确认验收

先说要什么。**这一步不花钱**，可以反复调。

```
你：换成 Q 版贴纸、1024 方形、透明底，尾鳍不要有白斑，先给我看提示词
调用：whale_meme(action="preview", task="task01", step="whole",
                 style="chibi-sticker", size="1024x1024",
                 background="transparent", extra=["尾鳍不要有白斑"])
```

```
✅ 出图计划已就绪（这是预览，没有出图、没有花费）。

任务 task01，这一步是 whole，模型 GPT Image 2.5 · Sunburst。
尺寸 1024x1024，质量档 xhigh，背景 transparent，预计 130+ 秒/张。

确认无误就出图：把 confirm 设为 true，并带上令牌 <64 位确认令牌>
令牌一次性、10 分钟有效、参数一改就失效。每确认一次 = 一次付费调用。

提示词全文：
【出图计划预览】task01 · whole · GPT Image 2.5 · Sunburst
…
```

> 上面这块里 **sha256 与令牌都换成了占位符** —— 它们由本次计划的内容与时间算出、每次都不同。
> 实际调用时是真值，直接原样复制到 `render` 的 `token` 参数即可。

**参数之间怎么相互作用**（都有实测依据）：

| 现象 | 解释 |
|---|---|
| 尺寸用了 1024×1024 而不是 1024×1536 | `chibi-sticker` 预设自带 1024²；你另传的 `size` 优先 |
| 产出文件名多了「_透明」 | 指定 `background: transparent` 时自动加后缀，避免覆盖不透明版本 |
| 质量档是 xhigh | 2.5 Sunburst 的推荐档；换模型会自动换成该模型支持的档 |
| 报错说「gpt-image-2 不支持透明底」 | 该模型不暴露透明底参数。这是**直接拒绝**，不会静默降级 |

计划的**每一条**都会进入令牌哈希：任务、步骤、模型、档位、尺寸、背景、输入图、提示词 sha256、产出文件名。
所以「先确认 A、再偷偷换成 B」是不可能的 —— 换了令牌就对不上。

看完确认无误，再说一句出图：

```
你：预览没问题，出图
调用：whale_meme(action="render", task="task01", step="whole",
                 style="chibi-sticker", size="1024x1024",
                 background="transparent", extra=["尾鳍不要有白斑"],
                 confirm=true, token="<preview 返回的令牌>")
```

**门禁**：不带 `confirm: true` 时只返回计划、绝不触发出图；令牌一次性、10 分钟有效、参数一改即失效；
失败也不会自动重试（重试要重新确认，避免重复计费）。

不想让插件出图，就用这条拿命令自己跑，其余环节完全一样：

```
你：出图的命令给我，我自己跑
调用：whale_meme(action="commands", step="whole", model="gpt-image-2.5-sunburst", quality="xhigh")
```

返回的是可直接粘贴的一整条命令（形如：

```
& '<python 解释器>' '<工作区>\_tools\whale_image_client.py' gen --model gpt-image-2.5-sunburst \
  --prompt-file '<工作区>\_tools\payloads\task01\21_整图__img25.txt' \
  --out '<工作区>\outs\task01_…\gpt-image-2.5-sunburst\05_整图一次出图_1024x1536.png' \
  --size 1024x1536 --quality xhigh --timeout 900
```

—— 真值里 `<python 解释器>` 与 `<工作区>` 是你的实际路径），
后面还跟着该步的操作要点（例如「第 0 步不能省：立绘是成熟比例，直接用立绘做后两格的输入会继承御姐比例」）。照做即可。

## 安装

### 方式 A：脚本（推荐，可回滚）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\install.ps1"
```

脚本按顺序做四件事，任何一步失败都自动回滚：

1. 备份 profile 的 `package.json`（`package.json.bak-whale-meme-<时间戳>`）
2. 在 `dependencies` 加一条 `"dsh-whale-meme": "link:<本目录>"`
3. 在 `dsh.profile.bundles` 末尾加一个条目
4. 在 profile 的 `node_modules` 下为本目录建 Junction（目录联接）

然后用 Node 复核清单合法性与解析链，最后提示重启。

> **为什么改 JSON 用 Node 而不是 PowerShell？** Windows PowerShell 5.1 的 `ConvertTo-Json` 会把
> 非 ASCII 字符转义成 `\uXXXX`，把本来中文可读的插件清单搞成不可读；而且历史上 DSH 的
> profile 清单曾被写入 UTF-8 BOM，导致启动时 JSON 解析失败、应用打不开。
> `scripts/patch-profile.mjs` 读写都不带 BOM，并保持原缩进与换行。

> **为什么两个 `.ps1` 带 UTF-8 BOM？** PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 GBK 读，
> 中文注释会变成语法错误。请勿用会去掉 BOM 的编辑器保存这两个文件。

### 方式 B：DSH 终端

DSH Desktop 的 `dsh` 命令**不写进系统 PATH**，用托盘菜单 **Open DSH Terminal** 打开：

```sh
dsh plugin --profile desktop add "link:<本目录绝对路径>"
```

### 安装后必须重启

DSH 插件在**应用启动时**装载。装完要**完全退出**桌面版（托盘右键 → 退出；关窗口只是隐藏），
再重新打开。用任务管理器确认没有残留的 `DeepSeek Harness` 进程。

### 卸载

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\uninstall.ps1"
```

优先恢复安装时留下的备份；没有备份时精确摘掉两个条目。无论哪种方式都会删除
`node_modules` 下的联接（**只删联接，不删本目录**）。沙箱实测：卸载后清单与安装前逐字节相同。

## 工具：`whale_meme`

14 个 action。`status`~`commands` 只读；`scaffold` / `init` / `build` **默认 dry-run**；
`render` **默认只出计划**，真出图必须显式确认。

### 只读校验

| action | 回答什么问题 |
|---|---|
| `status` | 工作区在哪、四个阶段归属谁、每个任务缺哪份文件、负载与产物现状 |
| `task` | 这个任务的逐字文案是什么、哪几个字必须加粗、五件套齐不齐 |
| `payload` | 投喂文本有没有被手打改写（磁盘字节 sha256 + 正文是否仍逐字出现在来源文件里） |
| `lineage` | 每一张产物到底是用哪份负载出的（元数据 `prompt.sha256` ↔ 负载索引） |
| `outputs` | 产物尺寸、透明通道、推荐交付件、元数据齐全度、异常尺寸 |
| `commands` | 某一步的逐字复现命令（`build`/`mother`/`upper`/`lower`/`whole`/`compose`/`check`/`index`） |

`payload` 是其中最有价值的一个：它同时校验**磁盘字节的 sha256 与索引记录一致**，且**负载正文仍逐字出现在
它声称的来源文件里**。这是「投喂文本没有被改写」的机器证据，也是这套流水线最容易出问题的一环。

### 会写盘的动作（默认 dry-run）

| action | 做什么 | 安全设计 |
|---|---|---|
| `init` | 补齐工作区缺的目录与占位文件 | 只创建、**不覆盖**；已存在的文件一字不改；不碰 `_tools/` 脚本 |
| `scaffold` | 新建任务骨架（五件套 + README） | 拒绝覆盖已占用任务号；先出计划，`write: true` 才落盘 |
| `build` | 按清单里的抽取计划从 `texts/` 逐字重建投喂负载 | 有 `assert` 断言防索引错位；**断言失败就一个文件都不写** |
| `fetch` | 从上游开源仓库 `EDMOK/blue-fish-archive` 下载角色参考素材 | **只往 `datas/` 写**；只取图片与 json（字体/图标/音频/网页一律不下）；写 `SOURCE.json` 记来源与许可；体积大的包会警告 |

### 素材下载与文案起草

| action | 做什么 |
|---|---|
| `fetch` | 按素材包（`character` / `samples` / `previews` / `large` / `media`，或 `all`）从上游下载参考图；默认 `character + samples + previews`（约 17 MB）；走 GitHub REST API，不依赖 git |
| `draft` | **一句自由需求 → 待填写草稿模板 + 校验清单**。插件不代写文案 —— 文案由 LLM 依需求产出 |
| `draftCheck` | 校验并结构化填好的草稿 → 返回**完整草稿供用户逐字复核修改**（含 `storyboardPreview`，已用同一套分镜解析器验证自洽） |

`draft` / `draftCheck` **都不落盘**（不在 `WRITING_ACTIONS` 里），文案要用户确认后才走 `scaffold` 写进 `texts/`。

### 提示词预览与出图

| action | 做什么 |
|---|---|
| `preview` | 把「文本之外的要求」（画风/尺寸/质量档/透明底/配色/附加要求/禁止项）规范化，组装出**最终要喂的完整提示词**，给出确认令牌 |
| `render` | **确认后直接出图**：默认只返回计划；带 `confirm: true` + `preview` 发的令牌才真正调用图像模型 |

`render` 的门禁规则（每一条都有测试守着）：

| 规则 | 为什么 |
|---|---|
| 不带 `confirm: true` 绝不出图 | 出图有费用，默认什么都不做 |
| 必须有 `preview` 发的令牌 | 保证确认的是**看到的那份**计划 |
| 令牌一次性 | 用掉即失效，重复使用被拒 |
| **计划不合法不发令牌** | 令牌代表「这份计划可以出图」，发给一份出不了的计划只会误导 |
| 计划一变令牌即失效 | 令牌把任务/步骤/模型/档位/尺寸/背景/输入图/提示词 sha256/产出文件名一起哈希 |
| 10 分钟有效 | 过期必须重新预览 |
| 每张一次调用 | 费用可控；批次由调用方一张张来 |
| 失败不自动重试 | 重试要重新确认，避免重复计费 |

### 返回什么：自然语言回复

每个 action 的返回值都同时有两种读者：

- **`reply` 字段**：一段自然语言状态回复，先说结论、再给数字、最后给下一步。界面默认显示的就是它。
- **结构化字段**：`ok`、`tasks`、`entries`、`planSummary` 等照旧全在，供代理与脚本判断。

例如 `status` 的 `reply`：

```
✅ 工作区在 F:\whale meme

四个阶段目录：datas✓  texts✓  _tools/payloads✓  outs✓

共 1 个任务：
  · task01 · 字符串替换把脚本改坏了
      提示词 5/5，投喂负载 7 份
      gpt-image-2：7 张图，交付件 05_整图一次出图_1024x1536.png
      gpt-image-2.5-sunburst：7 张图，交付件 05_整图一次出图_1024x1536.png

下一步：看某个任务的逐字文案用 task（例如 task="task01"）；确认投喂文本没被改过用 payload。
```

回复层的两条硬规则，都有测试守着：

1. **失败就是失败**：不会把失败说成「完成」，也不会在失败时给出「可以出图」的指引；
2. **回复层是附加物**：它自己出错时不影响结构化结果，只会在回复里说明「生成回复时出错」。

出图执行走工作区既有的 `_tools/whale_image_client.py`（不重复实现 HTTP），
并在提示词落盘后**再核一次 sha256**；返回里会指明客户端元数据里的 `prompt.sha256`
是否与本次计划一致 —— 这是投喂零改写的机器证据。

### 文本之外的要求

```jsonc
{ "action": "preview", "task": "task02",
  "style": "chibi-sticker",                     // 画风预设
  "size": "1024x1024", "quality": "xhigh",
  "background": "transparent",                  // 只对 gpt-image-2.5 系有效
  "palette": ["深藏青为主"],
  "extra": ["尾鳍不要有白斑", "气泡距顶端至少 5% 高度"],
  "avoid": ["第二个人物"],
  "panels": 1 }
```

画风预设：`anime-cel`（日系 Q 版赛璐璐，默认）/ `chibi-sticker` / `watercolor` / `flat-vector` /
`pixel-art` / `retro-anime-90s`，也可传自定义风格描述。

三条设计约束：

1. **不重写基础提示词** —— 要求以追加段落加在原文之后，原文逐字保留，预览里一眼能看出加了什么；
2. **禁止项改写成正向句子** —— 两个图像模型都没有负向词参数；
3. **凭据与「官方」措辞被直接拒绝** —— 前者不该进提示词，后者违反合规底线。


### 边界：它会做什么、不会做什么

| | 说明 |
|---|---|
| **能出图，但默认不出** | `render` 不带 `confirm: true` 时只返回计划；确认要带 `preview` 发的令牌，一次性、计划一改即失效 |
| **能写盘，但默认不写** | `scaffold` / `init` / `build` 都要显式 `write: true`；`init` 只创建不覆盖 |
| 不替你写文案 | `task` 只读 `00_*` 并结构化，绝不改写 |
| 不自动验收 | `outputs` 是机械检查，**不能替代** `04_验收清单.md` 的人眼逐字核对 |
| 失败不自动重试出图 | 重试要重新确认，避免重复计费 |
| 不发布、不上传 | 出图是调用图像 API；插件自身没有别的网络代码，也没有遥测 |
| 不碰工作区外的文件 | 唯一例外是安装/卸载脚本改 DSH profile（带备份、可回滚） |
| 不碰 `_tools/` 下的脚本 | 只读引用；出图也是调用那份既有客户端，不重写它 |

> 出图的费用与副作用由**调用方**承担：每确认一次 = 一次付费调用。插件把「确认」做成了一次性的令牌，
> 而不是一个可以复用的开关。

## 工作区约定

插件不改变你的目录结构，只是**读取并校验**它。它期望的工作区形态：

```
<工作区根>/
├── .whale/manifest.json        工作区清单：目录树 + 各任务的负载抽取计划
├── datas/                      角色与参考资料（只读基准）
│   └── 01_character/           人设速查 + 原始立绘
├── texts/                      成品提示词（一个任务一个 taskNN_* 目录）
│   └── taskNN_<标题>/
│       ├── 00_分镜与文案锁定.md      唯一权威文本源
│       ├── 01_提示词_GPT-Image-2.md
│       ├── 02_提示词_GPT-Image-2.5.md
│       ├── 03_无字底图与后期排版兜底.md
│       └── 04_验收清单.md
├── _tools/                     出图客户端与校验脚本
│   └── payloads/<task>/        由脚本从 texts/ 逐字抽取的投喂负载
└── outs/                       出图产物（一个模型一个子目录）
    └── <task>/<model>/
```

工作区根目录的识别判据（`lib/core.mjs` 的 `looksLikeWhaleWorkspace`）：下列特征命中 **≥2 条**即认定为工作区——
`_tools/whale_image_client.py`、`_tools/payloads/`、`datas/01_character/`、`texts/README.md`、`outs/INDEX.csv`。
判据刻意宽松但不至于误判普通目录；不匹配时用 `DSH_WHALE_ROOT` 显式指定。

目录缺失时用 `{ "action": "init" }` 补齐（先看计划，再 `write: true`）。

### 投喂负载的抽取计划

`.whale/manifest.json` 里为每个任务记录一段 `extraction` 计划，
让 `build` 能**不依赖工作区那份写死任务路径的 `build_payloads.py`** 重建负载：

```jsonc
{
  "id": "task01",
  "dirName": "task01_字符串替换把脚本改坏了",
  "extraction": {
    "payloads": [
      { "file": "10_母图_中性站姿.txt", "from": "02_提示词_GPT-Image-2.5.md", "block": 2,
        "source": "02_…§3 第0步（逐字）", "assert": "中性站姿全身母图" }
    ]
  }
}
```

- `block` 是 markdown 代码围栏的**序号（从 0 开始）**；
- `assert` 是**防错位的断言短语**，那一块里必须出现它，否则拒绝抽取。**别省这个字段**
  —— 索引错位抽错内容，代价是一次付费出图；
- 抽取口径与既有脚本一致（只做换行归一化、结尾一个换行、sha256 对磁盘字节取）。
  已用 task01 的 7 份负载逐一比对验证过：**sha256 全部相同**。

## 开发

```bash
node --test --test-concurrency=1 test/core.test.mjs test/plugin-smoke.test.mjs \
  test/features.test.mjs test/reply.test.mjs test/extensions.test.mjs test/integration.test.mjs
node scripts/selftest.mjs          # 对真实工作区跑全部 action 并断言结论
node scripts/selftest.mjs --json   # 机器可读报告；退出码 0 表示全部通过
```

六组测试各管一段：

| 文件 | 管什么 | 是否需要真实工作区 |
|---|---|---|
| `test/core.test.mjs` | 纯逻辑：解析、抽取、审计、命令生成、scaffold（跑在临时夹具上） | 否 |
| `test/plugin-smoke.test.mjs` | 宿主接线：工具注册、技能注册、契约注入、缺注册表时只告警不抛错（假 Cordis 上下文） | 否 |
| `test/features.test.mjs` | 非文本要求、提示词组装、出图计划与令牌门禁、init、负载重建 | 否 |
| `test/reply.test.mjs` | 自然语言回复：覆盖全部 action、失败不说成完成、不该给令牌时不给、回复层出错不影响结构 | 否 |
| `test/extensions.test.mjs` | 上游素材下载的路径映射与噪音过滤、唤醒词、自由需求起稿的校验 | 否 |
| `test/integration.test.mjs` | 真实工作区上的结论是否正确 | 是，不在时自动跳过 |

**没有构建步骤**：`lib/*.mjs` 是原生 ESM，DSH 直接加载。代价是没有静态类型，收益是不存在
「源码与产物不一致」这一类问题。修改源码立即生效（Junction 装法），不需要重新安装。

## 设计取舍

- **分层**：`lib/core.mjs`（纯逻辑，只依赖 `node:`）→ `lib/requirements.mjs` / `lib/payloads.mjs` /
  `lib/workspace.mjs`（计划与抽取，仍然是纯逻辑）→ `lib/tools.mjs`（action 分发）→
  `lib/index.mjs`（唯一的 DSH 接线层）。前三层脱离宿主就能测，测试里也确实这么测的。
- **定位失败不阻塞装载**：找不到工作区时插件照常装载，工具在每次调用时重新解析并给出可执行错误。
- **`subprocess` 不列为必需**：它是 `render` 才需要的可选能力。列为必需会让插件在缺少该服务的宿主上
  整个保持 pending —— 连只读工具都装不上，这比「出图不可用」糟糕得多。
- **契约注入是加分项**：宿主没有可用入口时只写一条 debug 日志；契约内容同时内嵌在技能正文里，不会丢。
- **出图默认什么都不做**：`render` 不带 `confirm` 时绝不触发子进程；令牌一次性、计划一变即失效。
- **写盘动作一律默认 dry-run**：`scaffold` / `init` / `build` 都要显式 `write: true`。
- **不重复实现 HTTP**：出图走工作区既有的 `_tools/whale_image_client.py`，
  重试、签名 URL 过期、浏览器 UA 这些坑留在那一处。
- **不重写基础提示词**：非文本要求以追加段落形式拼接，原文逐字保留，预览可核对。

## 常见问题

| 现象 | 处理 |
|---|---|
| 装完看不到 `whale_meme` | 没重启。完全退出托盘再打开 |
| 报「没有找到蓝色大肥鱼工作区」 | 设 `DSH_WHALE_ROOT` 指向工作区根目录 |
| 报「profile 没有 node_modules」 | 先用 DSH 终端装过任意一个插件，即可生成该目录 |
| `payload` 报 `payload-drift` | 负载被手打改写过，或上游 `texts/` 改了而负载没重建。重建后再出图 |
| `lineage` 报 `unknown-prompt` | 该产物用的负载已不在索引里（负载被重建或曾手打投喂） |
| `lineage` 报 `no-metadata` | 该产物没有元数据。本地拼合产物属正常；其它情况请检查 |
| `build` 说「清单里没有 extraction 计划」 | 按返回里的模板在 `.whale/manifest.json` 给该任务补一段；**别省 `assert`** |
| `build` 说「断言短语找不到」 | 索引错位了。核对 `block` 序号，不要绕过断言 |
| `render` 说「缺少 token」 | 先 `preview` 拿令牌；令牌一次性，用掉要重新 preview |
| `render` 说「令牌与当前计划不一致」 | 预览之后改了参数。重新 preview 再确认 |
| `render` 说宿主没有子进程能力 | 用 `commands` 拿命令自己执行（插件明确拒绝，不会静默失败） |
| `preview` 说「拿不到基础提示词」 | 该任务缺 `02_提示词_*.md`，或用 `rawPrompt` 直接给提示词正文 |
